## 1. 引言

### 1.1 目的

本文档定义基于 `myrtio-mqtt` 库开发的 **RV1106 MQTT 客户端** 的需求规格，作为后续概要设计、详细设计、编码实现与测试验收的依据。客户端运行于 RV1106 Linux 平台，通过 MQTT 协议与 MXS 云平台通信，实现打印机（3D 打印机）的远程登录、状态上报、GCODE 命令下发执行、文件下载、固件升级等业务功能。

### 1.2 范围

- 客户端连接管理（连接、心跳、重连、遗嘱）
- MXS MQTT 协议 V2.1.2 全量协议包编解码与业务处理
- 数据流与命令清单中定义的上行 FIFO 队列、下行分发、GCODE 子命令
- RV1106 平台适配（Linux 系统 + 交叉编译）
- 与云平台（MXS/MQTT Broker）的接口

不在范围内：

- 云平台服务端实现
- 打印机固件（Klipper）内核业务
- UI 层实现（仅提供接口）

## 2. 总体描述

### 2.1 产品视角

RV1106 MQTT 客户端作为打印机设备侧与 MXS 云平台之间的通信枢纽，替代原 ESP32 AT 模块方案，将 MQTT 协议栈由 C 嵌入式实现替换为基于 Rust（myrtio-mqtt）实现。

```
┌──────────────┐    ┌───────────────────────────────┐    ┌──────────────┐
│ 打印机业务层   │───▶│  rv1106-mqtt-client (Rust)     │───▶│   MXS 云平台   │
│ (Klipper/MR) │◀───│  连接管理/协议编解码/业务模块    │◀───│  MQTT Broker  │
└──────────────┘    └───────────────────────────────┘    └──────────────┘
```

> MR = Moonraker。打印机业务层为 **Klipper + Moonraker**（客户端经 Moonraker WebSocket 与 Klipper 交互，完成全部硬件读取/配置/控制，参考 guppyscreen）。

### 2.2 运行环境

| 项 | 要求 |
| --- | --- |
| 硬件平台 | RV1106（Cortex-A7 单核/双核，内置 Linux） |
| 操作系统 | Linux（Buildroot 定制 / 官方 SDK），支持标准 POSIX 网络栈 |
| Rust 目标 | `armv7-unknown-linux-gnueabihf` |
| 交叉工具链 | 参考 rust-libp2p 项目：`arm-rockchip830-linux-uclibcgnueabihf-gcc`（Rockchip 交叉工具链） |
| Rust 版本 | 1.90+（与 myrtio-mqtt 要求一致） |
| 网络能力 | WiFi / 以太网，TCP/IP，可选 TLS |
| 设备软件 | 本机运行 **Klipper + Moonraker**（WebSocket `ws://127.0.0.1:7125`），客户端经 Moonraker 完成**全部硬件读取/配置/控制**，不直接接触硬件 |
| 存储 | 支持配置文件持久化（设备 ID、key、版本等） |

### 2.3 约束与假设

1. **协议版本**：以《MXS MQTT 通信协议（V2.1.2）》为准，Topic 前缀 `GT/MXS/`（文档 R2 中固件侧使用 `GT/M2/` 前缀，本需求以 R1 协议文档为准，前缀可配置）。
2. **QoS**：业务消息全部 QoS=1（协议要求），连接/遗嘱消息按协议规定。
3. **消息体积**：单个消息 JSON 负载 ≤ 1024 字节（协议约束）。
4. **基础库**：以 `myrtio-mqtt` 为基础，不重新发明 MQTT 协议栈；在其上扩展平台 transport 与业务模块。
5. **无 OS 强耦合**：myrtio-mqtt 为 `no_std` 设计，本项目在 RV1106 Linux 上运行，需提供 Linux std 网络栈 transport 实现（`TcpStream`），并在必要时将客户端改为 `std` 可编译。
6. **单客户端实例**：同一时刻仅维护一条与 Broker 的活动连接。
7. **时区/时间**：系统需提供 RTC 或网络时间，用于时间戳字段。
8. **设备交互通道**：客户端所有与硬件相关的读取/配置/控制均经本机 **Moonraker（Klipper 平台）** 完成（参考 guppyscreen），不直接访问 MCU 串口/GPIO/传感器等硬件资源。

### 2.4 用户特征

- 终端用户：通过手机 App / 云平台远程查看打印机状态、下发打印任务。
- 运维人员：远程升级固件、查询文件列表、设备解绑。
- 开发者：集成 myrtio-mqtt 业务模块扩展。

## 3. 功能需求

### 3.1 连接管理

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-CONN-01 | 客户端应能配置 Broker 地址（域名或 IP）、端口（1883 明文 / 8883 TLS）、用户名密码、ClientID，支持 `mqtt://` / `mqtts://` URL 配置。 | 必须 |
| FR-CONN-02 | 客户端支持 MQTT v3.1.1 与 v5 协议协商（依据 myrtio-mqtt `v5` feature），默认 v3.1.1。 | 必须 |
| FR-CONN-03 | 连接参数：Keep Alive 按协议（60s 可配置）、Clean Session 按协议（登录成功前/后策略见 R1）、遗嘱消息 LWT（Topic `GT/MXS/LWT/{deviceId}`，payload 按协议）。 | 必须 |
| FR-CONN-04 | 支持断线自动重连：指数退避（如 1s/2s/4s/8s…上限 60s，可配置），重连次数无上限；重连成功后按协议重新完成登录流程。 | 必须 |
| FR-CONN-05 | 主动断连接口：提供优雅 `disconnect()`（发送 DISCONNECT，含 v5 会话清理语义）。 | 必须 |
| FR-CONN-06 | 连接状态回调/事件：`Connecting / Connected / LoginOk / Disconnected / Retrying / Reconnecting` 等状态机事件，供上层 UI 显示。 | 必须 |
| FR-CONN-07 | PINGREQ/PINGRESP 心跳保活按协议周期发送，超时判定断线并触发重连。 | 必须 |
| FR-CONN-08 | 同一 ClientID 冲突：Broker 踢线（新连接挤掉旧连接）时按协议行为处理（重新登录 / 上报）。 | 建议 |

### 3.2 订阅与主题

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-TOP-01 | 启动连接成功后订阅下行主题 `GT/MXS/DOWN/{deviceId}`（QoS=1）。 | 必须 |
| FR-TOP-02 | 下行主题前缀可配置（如 `GT/MXS/` vs `GT/M2/`），deviceId 由配置提供。 | 必须 |
| FR-TOP-03 | 上行发布主题 `GT/MXS/UP/{deviceId}`；遗嘱主题 `GT/MXS/LWT/{deviceId}`。 | 必须 |
| FR-TOP-04 | 支持按 myrtio-mqtt `MqttModule` 机制注册动态 Topic（`TopicRegistry`），业务模块可订阅自有主题。 | 建议 |

### 3.3 协议包编解码

依据 R1，客户端须实现以下协议包（全部 QoS=1，JSON 紧凑格式，无多余空格）：

| 编号 | 协议包 | 方向 | 说明 | 优先级 |
| --- | --- | --- | --- | --- |
| FR-PKT-01 | login | 上行/下行 | 登录请求 `{key, client_id, version, type, cmd:login}`；下行应答 `login:1` 表示成功 | 必须 |
| FR-PKT-02 | alarm | 上行 | 错误报警（含 error 码） | 必须 |
| FR-PKT-03 | status_hardware | 上行 | 硬件状态（固件版本等） | 必须 |
| FR-PKT-04 | status_temp_fan | 上行 | 温度/风扇状态 | 必须 |
| FR-PKT-05 | status_level | 上行 | 调平状态 | 必须 |
| FR-PKT-06 | status_print | 上行 | 打印状态（含打印进度、剩余时间等） | 必须 |
| FR-PKT-07 | status_query | 下行/上行 | 云端查询状态：下行触发，上行回复对应状态包 | 必须 |
| FR-PKT-08 | gcode | 下行/上行 | 下行下发 GCODE，上行返回执行结果（`gcode_seq` 关联） | 必须 |
| FR-PKT-09 | download_begin / download_end | 下行/上行 | 文件下载握手与结束确认 | 必须 |
| FR-PKT-10 | upgrade_query | 下行/上行 | 固件升级版本查询 | 必须 |
| FR-PKT-11 | file_list | 下行/上行 | 文件列表查询与返回 | 必须 |
| FR-PKT-12 | server_unbind / device_unbind | 下行/上行 | 解绑设备（云端主动/设备确认） | 必须 |
| FR-PKT-13 | 其余字段扩展 | 双向 | 按 R1 中字段表（设备型号、SN、Mac、状态等）逐一实现编解码，字段缺失/多余须容错 | 必须 |

**编解码共性需求：**

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-PKT-14 | 所有协议包 JSON 序列化/反序列化：紧凑格式、字段顺序固定、非法 JSON 不崩溃并记录日志。 | 必须 |
| FR-PKT-15 | 协议包 `cmd` 字段统一分发：上行包由对应业务模块构造，下行包按 `cmd` 路由到处理函数。 | 必须 |
| FR-PKT-16 | 未知 `cmd` / 未知字段：忽略并告警日志，不中断连接。 | 必须 |
| FR-PKT-17 | 消息大小上限校验（≤ 1024B），超限丢弃并告警。 | 必须 |

### 3.4 上行数据流与 FIFO 队列

依据 R2，上行消息需串行化发送（防止乱序）：

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-FIFO-01 | 实现上行 FIFO 队列，所有上行协议包按序入队、按序发送（QoS=1，等待 PUBACK）。 | 必须 |
| FR-FIFO-02 | 队满策略：FIFO 深度可配置（如 16），队满时丢弃最旧或阻塞（策略可配置），并记录告警。 | 必须 |
| FR-FIFO-03 | 高优先级消息（login、download 类）可插队（可选策略），保证登录先于业务数据。 | 建议 |
| FR-FIFO-04 | 队列与连接状态联动：断线期间可缓冲，重连成功后按序发送缓冲消息（超龄消息丢弃）。 | 必须 |
| FR-FIFO-05 | 提供发送接口给业务模块：`publish(cmd, payload)` 统一入口，内部完成 topic 构造、JSON 序列化、入队。 | 必须 |

### 3.5 下行命令分发与处理

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-DOWN-01 | 收到下行消息按 `cmd` 分发到对应 handler（gcode/download/upgrade_query/file_list/status_query/unbind/login 应答等）。 | 必须 |
| FR-DOWN-02 | gcode 命令：解析 `gcode_seq`、`gcode` 字符串，转发给打印机执行模块，执行完成后组装结果包上行（关联 `gcode_seq`）。 | 必须 |
| FR-DOWN-03 | GCODE 子命令完整清单（R2）：M20/M21/M23/M24/M25/M26/M27/M28/M29/M30/M32/M106/M115/M145/M150/M230/M524/M992/M994/M997/M998/M2000/M2001/G29 等，按 R2 逐条实现解析与执行结果映射。 | 必须 |
| FR-DOWN-04 | download_begin：按 R2 握手流程响应；download_end：确认数据完整性后应答。 | 必须 |
| FR-DOWN-05 | 3 分钟内无任何下行数据 → 判定链路异常，按 R2 策略触发重新登录/重连（次数限制可配置）。 | 必须 |
| FR-DOWN-06 | status_query：按查询类型返回对应 status 包。 | 必须 |
| FR-DOWN-07 | server_unbind：执行解绑流程并上行 device_unbind 确认。 | 必须 |

### 3.6 GCODE 执行结果

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-GC-01 | gcode 执行结果上行包格式严格按 R1/R2：`{cmd:"gcode", action:"result", gcode_seq, result, data}`。 | 必须 |
| FR-GC-02 | 每个下行的 `gcode_seq` 必须回包（成功/失败都要回，不遗漏）。 | 必须 |
| FR-GC-03 | 打印机忙时下行 gcode 应排队（本地 gcode 队列深度可配置），按序执行并回包。 | 必须 |
| FR-GC-04 | 执行失败（超时/拒收）须在结果中带错误码。 | 必须 |

### 3.7 状态上报

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-ST-01 | 状态上报策略：按 R2（打印中 3s 周期 / 空闲 60s 周期，具体周期可配置）。 | 必须 |
| FR-ST-02 | 状态变化（温度、打印进度、错误、调平）时触发即时上报（事件驱动 + 周期兜底）。 | 必须 |
| FR-ST-03 | 各 status 包字段（温度、风扇、打印百分比、剩余时间、坐标等）与 R1 字段表一致。 | 必须 |
| FR-ST-04 | 上报节流：高频变化字段（如温度）合并上报，避免消息风暴。 | 建议 |

### 3.8 模块化运行时

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-MOD-01 | 基于 myrtio-mqtt `MqttRuntime` + `MqttModule` 组织业务代码，每个协议域一个模块（login/alarm/status/gcode/download/upgrade/filelist/unbind）。 | 必须 |
| FR-MOD-02 | 模块生命周期：`register → start → poll → stop` 与连接状态联动。 | 必须 |
| FR-MOD-03 | 模块间解耦：模块通过 `Context` 发布消息/读取订阅，不直接相互调用（参考 myrtio-mqtt 示例）。 | 必须 |
| FR-MOD-04 | 每个模块支持独立启停开关（feature/配置），便于裁剪。 | 建议 |

### 3.9 配置管理

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-CFG-01 | 配置文件（TOML/JSON）持久化：Broker 地址、端口、TLS 开关、用户名/密码、ClientID、deviceId、key、固件版本、状态上报周期、重连策略等。 | 必须 |
| FR-CFG-02 | 配置热更新：运行时修改部分配置（如上报周期）即时生效。 | 建议 |
| FR-CFG-03 | 敏感配置（密码/key）支持环境变量或单独权限文件注入，日志中脱敏。 | 必须 |

### 3.10 日志与可观测性

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-LOG-01 | 分级日志（error/warn/info/debug/trace），支持输出到 stdout/syslog/文件。 | 必须 |
| FR-LOG-02 | 连接状态、重连次数、消息收发统计、FIFO 溢出次数等运行指标可查询。 | 建议 |
| FR-LOG-03 | 支持 `defmt` feature（与 myrtio-mqtt 一致）以降低日志开销（可选）。 | 建议 |

## 4. 接口需求

### 4.1 外部接口

| 编号 | 接口 | 说明 | 优先级 |
| --- | --- | --- | --- |
| IFR-NET-01 | TCP Socket | 基于 std `TcpStream` 实现 `MqttTransport`（myrtio-mqtt transport 抽象），支持 IPv4。 | 必须 |
| IFR-NET-02 | TLS | 可选 TLS（8883），使用 rustls 或 openssl 绑定（嵌入式裁剪考量，推荐 rustls + pki-types）。 | 必须 |
| IFR-NET-03 | DNS | 支持域名解析 Broker 地址。 | 必须 |
| IFR-NET-04 | 时间 | 获取系统时间戳（`std::time`），用于协议时间字段与上报。 | 必须 |

### 4.2 内部接口（对打印机业务层）

| 编号 | 接口 | 说明 | 优先级 |
| --- | --- | --- | --- |
| IFR-INT-01 | 状态输入 | 上层（Klipper/Moonraker，经 WebSocket `printer.objects.subscribe` 订阅，参考 guppyscreen）周期性或事件性推送状态（温度、打印进度、坐标等）→ 客户端模块组织 status 包。 | 必须 |
| IFR-INT-02 | GCODE 执行接口 | 客户端将下行 gcode 经 Moonraker `printer.gcode.script` 交给 Klipper 执行（Marlin→Klipper 行为转换，见概要设计 §8.4），执行结果经 `notify_gcode_response` 回读。 | 必须 |
| IFR-INT-03 | 文件下载接口 | 下载数据写入本地文件系统的接口（路径、大小、校验）。 | 必须 |
| IFR-INT-04 | 升级接口 | 触发固件升级（下载固件 → 校验 → 写入分区 → 重启）的接口。 | 必须 |
| IFR-INT-05 | 配置接口 | 读取/写入客户端配置。 | 必须 |

## 5. 非功能需求

### 5.1 性能

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| NFR-PERF-01 | 单消息处理耗时 ≤ 10ms（RV1106 性能下，JSON 编解码 + 分发）。 | 必须 |
| NFR-PERF-02 | 上行 FIFO 吞吐 ≥ 20 msg/s（QoS=1 串行，含 PUBACK 等待）。 | 必须 |
| NFR-PERF-03 | 连接建立 + 登录完成 ≤ 5s（正常网络）。 | 必须 |
| NFR-PERF-04 | 稳态内存占用：客户端核心 ≤ 2MB（不含文件下载缓冲），可用 myrtio-mqtt 的 `no_alloc`/heapless 特性控制。 | 必须 |
| NFR-PERF-05 | CPU 占用：空闲状态 ≤ 5%（状态上报周期内）。 | 建议 |

### 5.2 可靠性

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| NFR-REL-01 | 网络抖动/断网：自动重连（FR-CONN-04），恢复后业务数据不丢失（或按策略丢弃超龄消息）。 | 必须 |
| NFR-REL-02 | 进程崩溃恢复：意外退出后重启能重新连接并重新登录。 | 必须 |
| NFR-REL-03 | 内存安全：纯 Rust（无 unsafe 或最小化 unsafe），无内存泄漏、无悬挂引用。 | 必须 |
| NFR-REL-04 | 长时间运行（≥72h 连续）无资源泄漏、无消息堆积异常。 | 必须 |
| NFR-REL-05 | 并发安全：模块间通信通过 embassy-sync 通道，无数据竞争。 | 必须 |

### 5.3 可维护性 / 可测试性

| 编号 | 需求描述 | 优先级 |

| NFR-MNT-02 | 协议包编解码独立为可单元测试的纯函数（无 IO 依赖）。 | 必须 |

## 8. 风险与开放问题

| 编号 | 风险/问题 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| RSK-01 | myrtio-mqtt 为 `no_std`+embassy-net 设计，RV1106 需 std TCP transport | 需新增 transport 实现与 feature 适配 | 设计阶段将 `MqttTransport` 适配为 std `TcpStream`；必要时 fork 最小改动 |
| RSK-02 | 协议前缀 `GT/MXS/` 与固件实现 `GT/M2/` 不一致 | 消息路由错误 | 前缀配置化，联调前确认 |
| RSK-03 | myrtio-mqtt 对 MQTT v5 依赖 embassy-net；RV1106 云平台可能仅支持 v3.1.1 | 协商失败 | 默认 v3.1.1，v5 为 feature 开关 |
| RSK-04 | GCODE 子命令清单大（20+ 条），执行结果映射差异 | 集成返工 | 按 R2 逐条建立映射表，先在测试 broker 联调 |
| RSK-05 | 交叉编译工具链（uclibc gnueabihf）与 rustls 依赖兼容性 | TLS 无法启用 | 提前验证 rustls 在该目标链下编译；备选 openssl |
| RSK-06 | 时间戳依赖系统时间 | 状态包时间错误 | 确认系统 RTC/ntp 可用性 |
