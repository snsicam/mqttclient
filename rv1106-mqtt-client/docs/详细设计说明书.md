## 2 myrtio-mqtt API 核验结论与补丁清单（定稿）

### 2.1 API 核验结论

对 myrtio-mqtt v0.3.0 源码（R5）逐点核验，结论如下：

| 项 | 概要设计假设 | 核验结果 | 影响 |
| --- | --- | --- | --- |
| `MqttTransport` trait | async fn send/recv，可外部实现 | ✅ 原生 `#[allow(async_fn_in_trait)]` trait，`send(&mut self, buf: &[u8])` / `recv(&mut self, buf: &mut [u8]) -> Result<usize>`，`type Error` 关联类型 | **无需 trait 适配**，直接 impl |
| `MqttClient<MAX_TOPICS, BUF_SIZE>` | 泛型常量 | ✅ `MqttClient<'a, T, const MAX_TOPICS, const BUF_SIZE>` | 选型：`MqttClient<StdTcpTransport, 16, 2048>` |
| `MqttRuntime` | 由 Module 驱动 | ✅ `MqttRuntime::new(client, module, outbox_depth)`，`PublisherHandle` 线程安全 | 用 outbox 通道发布，脱离 embassy 信号量 |
| `MqttModule` | object-safe | ✅ `register/on_message/on_tick/on_start/last_will/needs_immediate_publish/on_publish` | 业务模块实现 trait 即可 |
| `TopicRegistry` | 注册订阅 topic | ✅ `register(topic)` 拷贝进静态缓冲 | 订阅集中注册 |
| LWT（遗嘱） | P2 需要补丁 | ✅ **`MqttOptions::with_last_will(LastWill)` 原生支持** | **P2 取消** |
| QoS | 上行 QoS1 | ✅ `PublishOutbox::publish(topic, payload, qos)` | 直接可用 |
| recv 缓冲 | P3 需复用 | ⚠️ `recv(&mut self, buf: &mut [u8])` 由调用方传缓冲，**复用是调用方责任** | **P3 降级为使用约定**，无需补丁 |
| embassy 依赖 | 与 std 共存 | ⚠️ `Cargo.toml` 依赖 embassy-net/embassy-time（Rust 2024） | P1 保持库改动最小 |

### 2.2 补丁清单（定稿）

| 编号 | 补丁 | 级别 | 说明 |
| --- | --- | --- | --- |
| P1 | **透传 embassy-time std driver feature** | Cargo | `myrtio-mqtt/Cargo.toml`：embassy-time 增加 `std` 特性（使其在 std 环境用系统时钟），**不启用 embassy-net 的 Ethernet**（仅 trait/类型），避免引入网卡驱动依赖 |
| **P1b** | **`MqttOptions` 支持 clean_session** | 代码（编码阶段新增） | R1 §2 要求 **Clean Session=0**（保持会话、接收离线 QoS1 消息），但 `MqttOptions` 无该配置项，且 `MqttClient::connect` 中 `Connect::with_credentials(..., true, ...)` 的 clean_session **写死 `true`** → 为 `MqttOptions` 增加 `clean_session` 字段（默认 `true`，保持上游兼容）与 `with_clean_session(bool)` 构造器，connect 中改用该字段 |
| P2 | ~~LWT 支持~~ | — | **取消**（原生支持） |
| P3 | ~~recv 缓冲复用~~ | — | **降级为使用约定**：`StdTcpTransport` 内部持有 `[u8; 2048]` 读取缓冲并切片返回，调用方（event_loop）逐包消费，避免重复分配 |
| P4 | 文档/示例补充（可选） | Docs | 补充 std 环境 TcpStream transport 示例到 README（对上游友好的贡献） |

> 结论：**myrtio-mqtt 无需功能性 fork**，以 `path` 依赖 + P1 feature 透传即可；P3 靠 StdTcpTransport 内部缓冲实现。
> 编码阶段（SPC 阶段 4）核验新增 **P1b**：`MqttOptions` 需支持 clean_session，否则无法满足 R1 的会话保持要求。

## 4 StdTcpTransport 详细设计

### 4.1 目标

在 Linux std 环境实现 `MqttTransport`，替代 embassy-net `TcpTransport`，连接远端 MQTT Broker（TCP 1883 或 TLS 8883）。

### 4.2 设计要点

- **非阻塞 + 轮询**：`std::net::TcpStream::set_nonblocking(true)`；`send` 用循环写直至写完（EMPTY 时 `yield_now` 等待）；`recv` 先尝试读取，`WouldBlock` 时 `yield_now` 重试，避免自旋。
- **内部缓冲**：`rx_buf: [u8; 2048]` 承载一次 recv 的原始字节；`recv(&mut self, out: &mut [u8])` 从内部缓冲复制到 `out` 并返回实际字节数（实现 P3 缓冲复用约定）。
- **连接建立**：`connect(addr) -> io::Result` 在 `MqttClient::new` 前由调用方完成；`StdTcpTransport::new(stream)` 接管。
- **TLS（可选 feature）**：`tls` feature 下包装 `rustls` 客户端流（RSK-05），默认关闭。
- **超时**：连接超时 10s；读写无数据超时由上层 keepalive 机制处理（MQTT 层心跳）。

### 4.3 伪代码

```rust
pub struct StdTcpTransport {
    stream: TcpStream,
    rx_buf: [u8; 2048],   // 内部读取缓冲（P3 约定）
    rx_len: usize,
    rx_pos: usize,
}

impl MqttTransport for StdTcpTransport {
    type Error = std::io::Error;

    async fn send(&mut self, buf: &[u8]) -> Result<(), Self::Error> {
        let mut off = 0;
        while off < buf.len() {
            match self.stream.write(&buf[off..]) {
                Ok(n) => off += n,
                Err(e) if e.kind() == WouldBlock => yield_now().await,
                Err(e) => return Err(e),
            }
        }
        Ok(())
    }

    async fn recv(&mut self, buf: &mut [u8]) -> Result<usize, Self::Error> {
        loop {
            if self.rx_pos < self.rx_len {   // 消费内部缓冲
                let n = (self.rx_len - self.rx_pos).min(buf.len());
                buf[..n].copy_from_slice(&self.rx_buf[self.rx_pos..self.rx_pos + n]);
                self.rx_pos += n;
                if self.rx_pos == self.rx_len { self.rx_len = 0; self.rx_pos = 0; }
                return Ok(n);
            }
            match self.stream.read(&mut self.rx_buf) {
                Ok(0) => return Err(ErrorKind::UnexpectedEof.into()),
                Ok(n) => { self.rx_len = n; self.rx_pos = 0; }
                Err(e) if e.kind() == WouldBlock => yield_now().await,
                Err(e) => return Err(e),
            }
        }
    }
}
```

### 4.4 与 MqttClient 的装配

```rust

stream.set_nonblocking(true)?;
```

## 5 Moonraker 客户端详细设计

### 5.1 连接与 WS 帧处理

- 端点：`ws://127.0.0.1:7125/websocket`（可配置）。
- 库选型（D13）：`tungstenite` 直接对接 `std::net::TcpStream`（`tungstenite::accept`），**不引入 tokio**；读/写帧封装为 async（非阻塞 + yield 轮询，同 §4 模式）。
- 心跳：每 10s 发送 `{"jsonrpc":"2.0","method":"server.info","id":n}`（同 guppyscreen 保活方式）；收到任何消息重置保活计时。
- 重连：指数退避 200ms→2s（max），无限重试；断连置 `moonraker_online=false`，恢复后重新订阅并全量拉取 `printer.objects.query` 重建 AppState。

### 5.2 JSON-RPC 2.0 请求-响应关联

- 每个请求分配单调递增 `id: u64`，维护 `pending: HashMap<u64, oneshot<Response>>`；
- 接收帧 → 解析 JSON：
  - 含 `"id"` → 查 pending，投递响应（`result` 或 `error`）；
  - 无 `"id"` 且 `"method":"notify_*"` → 通知分发（§5.3）；
  - 无法解析 → 日志 + 忽略。

```rust
enum WsIn {
    Response { id: u64, result: Value, error: Option<RpcError> },
    Notification { method: String, params: Vec<Value> },
}
```

### 5.3 通知分发

| 通知 | 处理 |
| --- | --- |
| `notify_status_update` | `params[0]` 增量对象 merge 进 AppState；标记 `state_dirty=true` 触发状态上报 |
| `notify_klippy_disconnected` | 置 Klipper 离线；生成 `alarm`（errType 按表 §8.5） |
| `notify_klippy_ready` | 置在线；重订阅 |
| `notify_gcode_response` | `params[0]` 文本 → 缓存最近一条，供 GcodeModule 关联执行结果 |
| `notify_webhooks_*` / `notify_filelist_changed` | 事件驱动 file_list 刷新/状态更新 |

### 5.4 订阅对象清单（首订阅 + 增量）

初始 `printer.objects.subscribe`（params: 对象列表）→ 之后仅依赖 `notify_status_update` 增量。清单（含硬件对象，D15）：

## 7 模块详细设计

### 7.1 连接状态机（细化）

状态：`Disconnected → Connecting → Connected(MQTT 3.1.1 CONNACK) → LoginPending(上行 login 包) → Online → (Downloading) / (BindFail)`；任意态失败 → `Reconnecting`（退避 1s→30s，3min 无下行分级重启）。

转移表（自 HDS-002 §6 细化）：

| 当前 | 事件 | 动作 | 下一态 |
| --- | --- | --- | --- |
| Disconnected | 启动/配置就绪 | 解析 broker 地址，TCP connect | Connecting |
| Connecting | CONNACK 0 | 注册订阅，发上行 login | LoginPending |
| Connecting | 失败/超时 | 退避重试 | Reconnecting |
| LoginPending | login ack ok | 启动周期上报 | Online |
| LoginPending | login 5s×3 无响应 | 重连 | Reconnecting |
| Online | 3min 无下行 | 分级：重连(1-2)→清参(3-4)→重启(5+) | Reconnecting/重启 |
| Online | MQTT 断连 | 置 offline，退避 | Reconnecting |

### 7.2 上行 FIFO（10 槽环形）

- 槽位：`[(topic, payload, priority, deadline, retry, ack_sem)]`，容量 10。
- 入队：满则丢最旧（保新）。
- 出队节拍：1s tick，按优先级（login > alarm > 状态 > 普通）出队。
- 重传：login 5s×3、download_end 1s×10、其余（状态/gcode 回复）3s×3（对齐 R2）。
- 直发（不走 FIFO）：login、upgrade_query、download_begin(OK)、download_end、file_list（HDS-002 D6）。

### 7.3 各业务模块（MqttModule 实现）

| 模块 | on_tick 周期 | 发布（上行） | 订阅（下行） | 依赖 |
| --- | --- | --- | --- | --- |
| LoginModule | —（on_start 一次） | login | — | 配置 device_id/key |
| StatusModule | busy 3s / idle 60s | status_hardware / status_temp_fan / status_level / status_print | status_query | AppState |
| GcodeModule | — | gcode 回复 | gcode | gcode_translator → moonraker.command |
| DownloadModule | 重传 1s | download_begin / download_end | download_begin / download_end | HTTP 下载 + files.upload |
| UpgradeModule | — | upgrade_query | upgrade_query / upgrade_start(如协议新增) | 版本查询/固件包 |
| FileListModule | — | file_list | file_list | moonraker files.list |
| UnbindModule | — | device_unbind / server_unbind | — | 配置清理 |
| AlarmModule | 事件 | alarm | — | AppState 异常/Moonraker 事件 |

### 7.4 下行分发（dispatcher）

下行包解码 → 分类 → 转发模块；模块内 `on_message` 同步处理，需要 Moonraker 交互的经 command 通道异步执行，执行结果（`notify_gcode_response`）经 outbox 回填 gcode 回复包。

### 7.5 心跳与 3min 无下行策略

- MQTT keepalive：60s（配置）；超时 1.5×keepalive 判定断连。
- 3min 无下行：计时器；触发分级（重连/清参/重启），重启前持久化需要保留的状态（device_id 保留、登录态清）。

## 8 协议结构体与 JSON（serde）

### 8.1 通用

- 序列化：serde + serde_json，`to_string` 紧凑模式；
- 负载校验：`payload.len() <= 1024`（超出返回错误并打日志）；
- 主题：`{prefix}/UP|DOWN|LWT/{deviceId}`（prefix 配置化，默认 `GT/MXS`）。

### 8.2 关键结构体示例

```rust
#[derive(Serialize)]
pub struct LoginUp { pub deviceId: String, pub key: String, pub version: String, /* … */ }
#[derive(Deserialize)]
pub struct GcodeDown { pub cmdType: String, pub gcode: String, pub num: u32, /* … */ }
#[derive(Serialize)]
pub struct StatusHardwareUp { pub deviceId: String, pub sd: u8, pub camera: u8, pub runout: u8, /* … */ }
```

> 全量字段映射见 HDS-002 §10 协议映射表（12 类包已全部落到 Rust struct），此处仅列代表。

## 14 实现偏差说明（编码阶段）

以下为编码实现与本文档设计的偏差，均已验证可行：

| 项 | 文档设计 | 实际实现 | 原因 |
| --- | --- | --- | --- |
| 异步运行时 | embassy-executor(std) | **移除**，改用 `futures::executor::block_on` 驱动主循环 | embassy-executor 0.7 无 `std` feature（0.7 拆分架构）；embassy-time 的 `std` feature 自带时钟驱动，无需 executor |
| 线程模型 | 全部走 embassy task | MQTT 主线程 + **moonraker 线程** + **dispatcher 线程**（`std::thread` + `mpsc`） | `MqttModule` 是**同步** trait，`on_message` 内无法 `await` Moonraker；故下行命令经通道交给独立线程执行，结果经事件通道回传 |
| `MqttRuntime` 生命周期 | — | `client_id` 与 publisher `Channel` 在 `main` 中一次性 `Box::leak`（进程级），每次重连复用 | `MqttRuntime<'a>` 的 `'a` 由 client_id 借用与 channel 共同决定，二者生命周期必须一致；仅在 `main` 分配可避免每次重连泄漏 |
| 模块内事件消费 | on_tick 中直接处理 | 先批量收集事件到 `Vec` 释放锁，再处理 | `self.event_rx.lock()` 的 guard 不能跨越 `&mut self` 调用（借用检查） |
| HTTP 下载 | — | ureq 3.4：`Config::builder().timeout_global()` + `Agent`；`resp.body_mut().read_to_vec()` | ureq 3.x 移除了 `RequestBuilder::timeout`，且 `Body` 不实现 `std::io::Read` |
| GCODE 转换 | 前缀匹配 | 精确解析 M 码数字（`mcode()` + `first_token()`） | 前缀匹配会导致参数错位，且 `M300` 被误判为 `M30` |
| `print_stats.state` 未知值 | — | 映射为 **Idle(0)** | 避免未知状态误报为 Error(5) 触发云端告警（原误映射 Standby，已修正对齐 R1 §5.3） |
| `PrintState` 枚举顺序 | — | 0 空闲 / 1 打印 / 2 完成 / 3 暂停 / 4 失败 / 5 取消 | OQ 核对中发现顺序错乱，已按 R1 §5.3 修正并补充单测 |
| `bindState` 判定 | — | `bound = (bind_state == 0)` | OQ 核对中发现判定反写（原 `== 1`），已按 R1 §5.1 修正：0=已绑定 / 1=未绑定 / 2=未录入 |
| `embassy-net` 依赖 | 硬依赖 | 改为 **optional**（std 平台不启用），`TcpTransport` 等 gate 在 `embassy-net` feature 下 | 本项目走 std `StdTcpTransport`，移除 embassy-net 避免拉入 `embassy-executor-timer-queue` 等仅异步执行器下才提供的符号（P2） |
| `embassy-time` 队列 | 集成队列（默认） | 启用 `generic-queue-8` 改用通用队列 | 集成队列引用 `__embassy_time_queue_item_from_waker`（需 embassy-executor 提供），本项目用 `futures::block_on` 无 executor；切换后链接通过（P3） |
| `getauxval` 符号 | — | 预编译 `cross/libgetauxval.a` 桩并链接 | Luckfox uclibc 1.0.31 不导出 `getauxval`（Rust std 栈溢出保护与 ring 0.17 调用），提供最小桩（AT_PAGESZ→4096，其余→0）解决（P4） |
| 重连延时 | `embassy_time::Timer::after` | 改为 `std::thread::sleep(5s)` | 无 embassy executor 时 `Timer::after` 无法工作（同上定时器队列驱动缺失）；`block_on` 单线程下同步 sleep 语义等价（P5） |
