## 1 引言

### 1.1 目的

本文档为 RV1106 平台上基于 `myrtio-mqtt` 库开发的 MQTT 客户端提供**概要设计**，描述系统总体架构、关键设计决策、模块划分、协议数据模型与配置设计，为 SPC 阶段 3（详细设计）和阶段 4（编码）提供依据。

### 1.2 范围

- 覆盖：MQTT 连接管理、上行发送（FIFO/直发/重传）、下行分发、12 类协议包处理、**与 Moonraker 的全部设备交互**（状态读取、硬件读取/配置/控制、命令下发、文件操作）、配置、交叉编译部署。
- 不覆盖：HTTP 文件/固件传输实现、Wi-Fi 配网（BluFi）、Klipper 运动控制与宏实现本身、Moonraker 服务器实现、云端服务器实现、**任何直接硬件访问（MCU 串口/GPIO/传感器，全部经 Klipper+Moonraker）**。

### 1.4 术语

| 术语 | 说明 |
|---|---|
| 上行 | 设备 → 服务器（`UP` 主题） |
| 下行 | 服务器 → 设备（`DOWN` 主题） |
| LWT | Last Will Testament 遗嘱消息 |
| FIFO | 上行发送队列（10 槽环形） |
| 模块 | 实现 `MqttModule` trait 的业务单元 |
| **Moonraker** | Klipper 的 API 服务器（本机 `127.0.0.1:7125`），提供 WebSocket/HTTP JSON-RPC 接口 |
| **Klipper** | 3D 打印机运动控制固件（RV1106 上运行） |
| **guppyscreen** | 基于 Moonraker 的触摸屏 UI 参考实现（工作区），其 WebSocket 客户端模式作为本客户端 Moonraker 对接参考 |
| **AppState** | 客户端内部聚合的打印机状态快照（由 Moonraker 订阅数据驱动） |
| **硬件对象** | Klipper 中声明硬件的对象（`temperature_sensor`/`output_pin`/`led`/`fan`/`runout_sensor` 等），客户端经 Moonraker 订阅/控制，**不直接访问硬件** |
| RT 任务 | 常驻异步任务（连接、周期上报、重传、下行分发、moonraker 订阅） |

## 2 设计目标与约束

### 2.1 设计目标（对照 SRS）

| SRS 条目 | 目标 |
|---|---|
| NFR-PERF-01 | 单条负载 ≤1024B，MQTT 报文缓冲 ≥2048B |
| NFR-REL-01 | 断线自动重连；分级重启策略对齐固件 |
| NFR-MNT-01 | 全部参数可配置（TOML），不改码即可适配云端 |
| NFR-PORT-01 | 交叉编译目标 `armv7-unknown-linux-gnueabihf` |
| IFR-MQ-01 | 与 R1 协议 12 类包字段完全一致（含兼容差异项） |
| IFR-INT-01 | **设备状态与全部硬件相关的读取、配置、控制均经 Moonraker 完成，客户端不直接接触任何硬件**（参考 guppyscreen） |
| IFR-INT-02 | **平台为 Klipper**：R2 固件（M2/M1S，Marlin）仅为行为参考，其 GCODE 命令与硬件行为整体转换到 Klipper 生态 |

### 2.2 技术约束

- 基础库 `myrtio-mqtt` 为 **no_std + embassy 生态**（embassy-time / embassy-net / embassy-sync），其 `MqttClient` 与运行时天然与传输层解耦，可替换 transport。
- 运行平台为 **RV1106 Linux（std 环境）**：无 embassy-net 网络栈，需自建 TCP 传输。
- **本机运行 Klipper + Moonraker**：**所有与硬件相关的读取、配置、控制均通过 Moonraker API 完成**（WebSocket `ws://127.0.0.1:7125/websocket`，JSON-RPC 2.0）；客户端不直接访问 MCU 串口、GPIO、`/sys/class`、传感器等任何硬件资源。Klipper 主机端经串口连接 MCU，Moonraker 是客户端唯一上层接口。
- **本项目为 Klipper 平台**：R2 固件（M2/M1S，Marlin）仅为**行为参考**，其 GCODE 语义与硬件行为（温度/风扇/LED/断料/门磁/调平/U盘/打印控制）需**整体转换**到 Klipper 生态（对象订阅/命令/宏），而非照搬执行。
- 单核嵌入式 SoC，资源有限：异步运行时采用轻量线程执行器，避免引入 tokio 全量依赖（WebSocket 库选择需与该约束一致，见 D13）。
- JSON 需紧凑序列化（无缩进/空格）、UTF-8，负载上限 1024B。

## 3 总体架构

### 3.1 分层架构

```
┌─────────────────────────────────────────────────────────────────────┐
│  本机：Klipper（主机端，经串口连接 MCU）+ Moonraker（API 服务器）       │
│   - 唯一设备交互通道：对象订阅/读取 printer.objects.subscribe|query     │
│     （状态/温度/风扇/LED/断料/门磁/调平/U盘 等硬件对象）                 │
│   - 控制/配置：printer.gcode.script / printer.print.* / files.*        │
│   - 客户端不直接访问任何硬件（零硬件耦合）                             │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ WebSocket JSON-RPC 2.0
┌──────────────────────────────▼──────────────────────────────────────┐
│ ①' Moonraker 客户端层（参考 guppyscreen KWebSocketClient/NotifyConsumer）│
│     moonraker/ws_client.rs   连接/心跳/重连/JSON-RPC 请求-响应/通知分发 │
│     moonraker/state_bridge.rs 对象订阅 → AppState 快照与增量更新        │
│     moonraker/command.rs     gcode.script / print.* / files.* 封装    │
└───────┬───────────────────────────────────┬──────────────────────────┘
        │ 状态事件 / 命令响应（上行）          │ 命令请求（下行）
┌───────▼───────────────────────────────────▼──────────────────────────┐
│ ① 业务模块层（MqttModule 实现，同步逻辑 + PublishOutbox）             │
│    LoginModule │ StatusModule │ GcodeModule │ DownloadModule │        │
│    UpgradeModule │ FileListModule │ UnbindModule                      │
└───────┬───────────────────────────────────┬──────────────────────────┘
        │ 上行（FIFO 入队 / 直发）            │ 下行（on_message 分发）
┌───────▼───────────────────────────────────▼──────────────────────────┐
│ ② 协议层：protocol/（serde 模型 + 编解码 + 1024B 校验）                │
│    上行编码器 UplinkEncoder │ 下行解码器 DownlinkDecoder               │
└───────┬───────────────────────────────────┬──────────────────────────┘
        │ publish(topic,payload,qos)         │ poll() → MqttEvent
┌───────▼───────────────────────────────────▼──────────────────────────┐
│ ③ 运行时层：MqttRuntime（模块注册/时钟/即时发布）+ 任务调度              │
│    uplink/sender（FIFO 出队节拍）│ uplink/retry（login/download_end）   │
│    downlink/dispatcher（按 type 分发）│ state/conn_state（状态机）       │
└───────┬──────────────────────────────────────────────────────────────┘
        │ MqttClient<T, MAX_TOPICS, BUF_SIZE>
┌───────▼──────────────────────────────────────────────────────────────┐
│ ④ MQTT 客户端层：MqttClient（连接/订阅/发布/poll）                      │
└───────┬──────────────────────────────────────────────────────────────┘
        │ MqttTransport trait（send/recv）
┌───────▼──────────────────────────────────────────────────────────────┐
│ ⑤ 传输层：transport/std_tcp.rs（StdTcpTransport）│ tls.rs（可选）       │
│     std::net::TcpStream 非阻塞轮询封装                                  │
└──────────────────────────────────────────────────────────────────────┘
```

**数据流总览**：

```
上行方向：Moonraker notify_status_update（含全部硬件对象：温度/风扇/LED/断料/
         门磁/调平/U盘/打印）→ state_bridge 更新 AppState
         → StatusModule 按周期读取 AppState → MQTT 状态包 → FIFO → 服务器
下行方向：服务器 MQTT 下行 → dispatcher → 业务模块
         → GcodeModule/DownloadModule 经 moonraker/command 下发命令/脚本/宏
           （所有硬件读取/配置/控制均经此通道）
         → Klipper 执行 → notify_status_update / notify_gcode_response 回读
```

### 3.3 线程/任务划分

采用 **embassy-executor（std feature，线程执行器）**，避免引入 tokio。任务划分：

| 任务 | 职责 | 触发 |
|---|---|---|
| conn_task | TCP 连接 + `MqttClient::connect` + 订阅 DOWN/LWT | 上电 / 断线 |
| runtime_task | `MqttRuntime::run`：驱动模块 on_tick / on_message / 即时发布 | 常驻 |
| uplink_task | FIFO 出队（默认 1s/个）→ publish | 常驻，仅 Online 态工作 |
| retry_task | login 重发（5s×3）、download_end 重发（1s×10） | 相应状态挂起 |
| **moonraker_task** | Moonraker WebSocket 连接、订阅、`notify_status_update`/`notify_gcode_response` 分发 → 更新 AppState + 通知相关模块 | 常驻（Klipper 在线） |
| watchdog_task | 3min 无下行检测 + 分级重启 | 常驻 |

> 简化方案：conn_task 与 watchdog 合并为单任务状态机（§6），实际以详细设计定稿。
> **Moonraker 断连 ≠ MQTT 断连**：Moonraker 掉线时 MQTT 连接保持，状态包按"状态不可用"策略发送（§16 RSK-08）。

## 4 关键设计决策

| 编号 | 决策 | 理由 / 备注 |
|---|---|---|
| D1 | MQTT 版本 **3.1.1**（`MqttVersion::V3_1_1`） | R1 §4.1；Clean Session=false，KeepAlive=60s |
| D2 | 运行时 = embassy-executor(std) + embassy-time(std driver) | 与 myrtio-mqtt 生态一致；避免 tokio 双运行时桥接 |
| D3 | **新增 StdTcpTransport** 实现 `MqttTransport`，替代 embassy-net `TcpTransport` | embassy-net 在 Linux 不可用；`MqttClient` 传输泛型可替换 |
| D4 | JSON 用 `serde` + `serde_json`；序列化默认无空格（紧凑）；发布前校验 ≤1024B | 满足 R1 §4.4/§4.5；std 平台可用全量 serde_json |
| D5 | 主题前缀**配置化**，默认 `GT/MXS`，可切 `GT/M2`/`GT/M1S` | R2 §一 指出固件与协议文档前缀不一致；联调前需与云端确认（OQ-01） |
| D6 | 上行发送策略对齐固件：login / upgrade_query / download_begin(OK) / download_end / file_list **直发**；alarm / 4 状态包 / gcode 回复 / device_unbind **入 FIFO** | R2 §二；避免与 file_list 分页发布冲突、保证串行化 |
| D7 | 重传/保活参数对齐固件并可配置：login 5s×3、download_end 1s×10、3min 无下行分级重启 | R2 §九 |
| D8 | TLS 作为可选 feature（`--features tls`，8883），默认关闭（1883 明文） | RSK-05：rustls/ring 交叉编译风险；降低首版风险 |
| D9 | 全部业务参数集中 TOML 配置 + 代码默认值 | NFR-MNT-01 |
| D10 | myrtio-mqtt 以 **path 依赖**纳入 workspace；改动以最小补丁形式维护（补丁清单见 4.1） | 便于快速跟进上游；限制改动面 |
| **D11** | **Moonraker 为客户端唯一设备交互通道**（WebSocket JSON-RPC 2.0，参考 guppyscreen 的 KWebSocketClient + NotifyConsumer 模式）：状态读取经 `printer.objects.subscribe` + `notify_status_update` 增量驱动 AppState；**一切硬件读取/配置/控制（温度、风扇、LED、蜂鸣器、断料、门磁、调平、U盘、打印）均经 Moonraker 对应对象/命令/宏完成**，客户端不直接访问任何硬件资源 | IFR-INT-01；guppyscreen 已在 RV1106 生态验证该链路 |
| **D12** | **命令下发经 Moonraker `printer.gcode.script` / `printer.print.*` / `server.files.*` / `printer.objects.query`**；R2 固件（Marlin）的 **GCODE 语义与硬件行为整体转换到 Klipper 生态**：M 码→Klipper 命令/`gcode_macro` 宏/对象操作，无法转换返回 `ERR`（见 8.4） | 本项目是 Klipper 平台；Marlin 仅为行为参考（RSK-07） |
| **D13** | **WebSocket 客户端**：优先 `tungstenite`（纯 Rust，`async` 封装自定义 IO，与 StdTcpTransport 相同轮询模式）；备选 `async-tungstenite`（smol/async-std 后端），**不引入 tokio** | 与 D2 运行时约束一致；实现方式列入阶段 3 定稿 |
| **D14** | **告警来源 = Moonraker 事件**：`notify_klippy_disconnected` / `print_stats.state=error` / 温度错误（extruder.temperature 异常）等，转换为 `alarm` 包 | R1 errType 0–21 映射表见 §8.5 |
| **D15** | **硬件交互对象化，抽象全部落在 Klipper 配置层**：LED、蜂鸣器、断料、门磁、灯等在 Klipper 侧用 `led`/`output_pin`/`runout_sensor`/`gcode_macro`/`temperature_sensor` 等对象声明（Klipper 配置由平台侧维护）；客户端经 Moonraker 订阅读取、经宏/命令控制，**配置差异通过 §10.4 映射表与 §11 配置适配** | 客户端零硬件耦合；硬件实现细节与引脚分配由 Klipper 配置承载 |

## 5 传输层设计（StdTcpTransport）

### 5.1 对 `MqttTransport` trait 的适配

`myrtio-mqtt` 的 `MqttTransport` 要求实现异步 `send`/`recv` 及关联错误类型（`TransportError: Debug`）。`StdTcpTransport` 设计：

```rust
pub struct StdTcpTransport {
    stream: TcpStream,            // std::net::TcpStream，设为非阻塞
    read_buf: [u8; BUF_SIZE],     // BUF_SIZE = 2048
    read_len: usize,
    addr: SocketAddr,
}

impl MqttTransport for StdTcpTransport {
    type Error = TransportError;
    // 注意：trait 的 async fn 若基于 embassy-executor poll，
    // recv() 内采用"非阻塞读 + embassy-time sleep 轮询"，见 5.3
}
```

要点：

- **非阻塞 + 轮询**：`TcpStream::set_nonblocking(true)`；`read` 返回 `WouldBlock` 时 `embassy_time::Timer::after(10ms)` 后重试。MQTT 为低频报文，10ms 轮询开销可忽略，且避免阻塞线程执行器。
- 实现时须与 myrtio-mqtt 的 trait 签名核对（其 `TcpTransport` 为 embassy-net 实现，见 `transport.rs`）。若 trait 要求 `recv` 返回 `&[u8]` 引用，StdTcpTransport 内部缓冲需保活至下一次 recv 调用。
- 连接建立：`TcpStream::connect(addr)` 阻塞调用放到独立线程或连接任务中完成（连接阶段不阻塞 executor）。

### 5.2 连接建立与拆除

```
conn_task:
  resolve host:port → TcpStream::connect（超时 10s，可配）
  → StdTcpTransport::new(stream)
  → MqttClient::new(transport, options)
  → client.subscribe(DOWN_TOPIC, QoS1)   // 订阅下行主题
  → （若配置订阅 LWT）client.subscribe(LWT_TOPIC, QoS1)
  → 通知 runtime_task 启动
拆除：stream.shutdown() / drop；进入 Reconnecting（§6）
```

### 5.3 超时与缓冲

| 项 | 值 | 说明 |
|---|---|---|
| 连接超时 | 10s（可配） | TCP connect |
| 读轮询间隔 | 10ms | 非阻塞轮询 |
| 读缓冲 | 2048B | > 1024B 负载 + MQTT 固定头/属性 |
| 写缓冲 | 2048B | 单包写 |

### 5.4 TLS 扩展（可选，feature `tls`）

- `rustls`（`rustls::StreamOwned` 包装 `TcpStream`）实现同一 trait 的另一实现 `TlsTransport`；CA/客户端证书路径入配置。
- 交叉编译：rustls 默认 provider（aws-lc-rs/ring）在 armv7 uclibc 工具链下可能编译失败（RSK-05）；备选 `rustls-rustcrypto`（纯 Rust）或降级明文。**首版默认关闭 TLS**。

## 6 连接状态机

### 6.1 状态定义

| 状态 | 含义 |
|---|---|
| `Disconnected` | 初始 / 断连（未尝试重连） |
| `Connecting` | TCP 连接 / CONNECT 报文 / 等待 CONNACK |
| `Connected` | MQTT 连接已建立（CONNACK 收到），已订阅，未业务登录 |
| `LoginPending` | 已发 login 包，等待服务器 login 回复（5s×3 重发） |
| `Online` | login 成功（bindState=0），周期上报开启 |
| `BindFail` | login 回复 bindState=1/2（未绑定/未录入），记录并按策略处理 |
| `Downloading` | 文件/固件下载中（暂停周期上报，R2 §6.2） |
| `Reconnecting` | 重连退避中 |

> Moonraker 在线状态独立跟踪（`moonraker_online: bool`），不参与 MQTT 状态机迁移，但影响状态包内容（§16 RSK-08）。

### 6.2 状态转移表

| 当前态 | 事件 | 动作 | 次态 |
|---|---|---|---|
| `Disconnected` | 上电 / 配置加载 | 发起连接 | `Connecting` |
| `Connecting` | CONNACK(成功) | 订阅 DOWN/LWT；发 login（直发） | `LoginPending` |
| `Connecting` | 连接失败 / 超时 | 记失败；退避 | `Reconnecting` |
| `LoginPending` | 收到 login 回复 bindState=0 | 存 account；触发全量状态包入队；开启周期上报 | `Online` |
| `LoginPending` | 收到 bindState=1/2 | 记录/上报 alarm；按策略（OQ-04） | `BindFail` |
| `LoginPending` | 5s 超时，重发 <3 次 | 重发 login | `LoginPending` |
| `LoginPending` | 5s 超时，累计 3 次 | 记失败；失败 ≥5 次触发重建连接 | `Reconnecting` |
| `Online` | 收到 download_begin 且校验通过 | 暂停周期上报 | `Downloading` |
| `Online` | 收到 server_unbind / device_unbind | 清绑定；可选重连 | `Online`（绑定清空） |
| `Downloading` | download_end 流程结束 | 恢复周期上报 | `Online` |
| `Online/Downloading` | 网络错误 / 心跳失败 | 断开，退避重连 | `Reconnecting` |
| `Reconnecting` | 退避结束 | 发起连接 | `Connecting` |
| 任意 | 3min 无下行（前置条件满足，§6.3） | 分级重启 | `Reconnecting`/`Connecting` |

### 6.3 分级重启策略（对齐 R2 §九）

3min 无下行检测前置条件：已登录 + 无登录流程 + 无下载流程 + 无固件流程。

| 累计次数 | 动作 |
|---|---|
| 1–2 | 重建 MQTT 连接（Clean Session 保持 0） |
| 3–4 | 清参数重配（重发 login 全流程） |
| 5+ | 重启进程 / 通知平台复位 |

## 7 上行链路设计

### 7.1 上行包分类

| 发送方式 | 包类型 | 重传策略 |
|---|---|---|
| 直发（不经 FIFO） | `login` | 5s×3（retry_task） |
| 直发 | `upgrade_query` | 无（按状态恢复） |
| 直发 | `download_begin`(transState=OK) | 无 |
| 直发 | `download_end` | 1s×10，等 `ackState`（retry_task） |
| 直发（分页） | `file_list` | 无（阻塞式逐页） |
| FIFO | `alarm`、`status_hardware`、`status_temp_fan`、`status_level`、`status_print`、`gcode`(回复)、`device_unbind` | 无（QoS1 由 MQTT 层保证） |

### 7.2 FIFO 结构

```rust
pub struct UplinkFifo {
    buf: [UplinkItem; FIFO_CAPACITY],   // FIFO_CAPACITY = 10（可配）
    head: usize, tail: usize, len: usize,
}
pub enum UplinkItem {
    Alarm(AlarmUplink),
    Status(StatusKind),      // Hardware | TempFan | Level | Print
    GcodeReply(GcodeReply),
    DeviceUnbind,
}
```

- **满则丢弃最旧**（对齐固件行为），并记日志。
- 入队接口为业务模块 `on_tick` / 事件回调中的同步调用，出队由 `uplink_task` 节拍驱动。

### 7.3 调度节拍与优先级

- 出队节拍默认 1000ms/个（可配）。
- `file_list` 发送期间（`publishing_filelist` 标志）暂停 FIFO 出队，避免与分页发布串扰（对齐 R2 §6.4）。
- 优先级顺序：直发包 > file_list 分页 > FIFO 出队。

### 7.4 重传机制（retry.rs）

| 流程 | 参数（默认） | 成功条件 | 失败处理 |
|---|---|---|---|
| login | 超时 5000ms，重发 ≤3 次 | 收到 `type=login` 下行 | 累计失败 ≥5 → 重建 MQTT 连接 |
| download_end | 间隔 1000ms，重发 ≤10 次 | 收到 `download_end` 下行 `ackState=OK/ERROR` | 放弃；记录；重置登录状态 |

### 7.5 状态上报周期（status_module）

| 条件 | 默认间隔 | 触发 |
|---|---|---|
| 打印中 / 加热中 / 喷嘴>50℃ / 调平中（据 AppState 判定） | 3s | 周期上报 4 个状态包 |
| 空闲 | 60s | 周期上报 4 个状态包 |
| 登录成功 / status_query / GCODE 状态变化（notify_status_update） | 立即 | 全量或增量状态包 |

> 状态数据来源：`AppState`（由 Moonraker 订阅驱动，§5A.4 / §10.4）。Moonraker 不可用时状态包携带"状态未知"标记或跳过（RSK-08）。
> 注：R2 §6.1 固件为忙 3s/闲 60s；R1 §5.3 文档为忙 10s/闲 5min，二者不一致。新客户端以配置为准（默认 3s/60s，OQ-05 与云端确认）。

## 8 下行链路设计

### 8.1 分发器（dispatcher）

下行消息经 `MqttRuntime::on_message` 回调进入各模块；此外独立 `dispatcher` 维护「命令→处理流程」表，用于协调跨模块状态（如 download_begin 需要 StatusModule 暂停、GcodeModule 触发状态包）。

| 下行 type | 处理模块 | 行为 | 回复 |
|---|---|---|---|
| `login` | LoginModule | bindState=0→Online+全量状态；1/2→BindFail | 全量 4 状态包 |
| `status_query` | StatusModule | 立即上报全量状态 | 4 状态包 |
| `gcode` | GcodeModule | 解析 gcodeCmd→**翻译层→Moonraker `gcode.script`**→收集响应→回复 | `gcode`(execResult) |
| `download_begin` | DownloadModule | 校验 U盘/忙闲/url 或 serverIp+fileName | `download_begin`(transState/errCode) |
| `download_end` | DownloadModule | ackState 停止 retry | 无 |
| `upgrade_query` | UpgradeModule | 判断 mcuFile/espFile 有无新固件 | 后续走 download 流程 |
| `file_list` | FileListModule | 延迟 500ms（FIFO 排空）→ **`server.files.list` 查询 U盘** | `file_list` 分页 |
| `server_unbind` | UnbindModule | 清绑定 + 存配置 | 无 |
| `device_unbind` | UnbindModule | 同上 | 无 |

### 8.2 处理流程要点

- **gcode**：装卸料中直接丢弃（对齐 R2 §四）；命令经 **GCODE 翻译层**（§8.4）转为 Klipper 命令序列经 `printer.gcode.script` 下发；回复带 `cmdType` + `execResult`（R1 V2.0.9；固件未实现，新客户端按协议实现，OQ-06 与云端确认是否必须）。
- **download_begin**：`download_step_state != NOCMD` → 忽略；无 U盘 → errCode=2；忙 → errCode=1；url 非空 → 直连 URL，否则 serverIp+fileName。回复 OK 直发，错误走 FIFO。
- **download 完成**：原固件逻辑为服务器随后下发 M32+M24（打印）或 M997（升级）；本设计经 Moonraker 下发等价命令（`printer.print.start` / 宏），见 §12.3。
- **file_list**：经 `server.files.list`（根目录或指定目录）获取；每包 ≤10 个文件；`fileTotal`=页数，`fileIndex` 从 1 起；无文件发空列表。

### 8.3 与 `MqttModule` 的适配

`MqttModule::on_message` 为**同步回调**且不能直接发布（借用 client 缓冲）。设计规则：

1. `on_message` 内解析 + 更新模块状态 + 置"待响应"标志；
2. `on_tick` / `needs_immediate_publish` 返回非零间隔时，经 `PublishOutbox` 入队响应；
3. 需要跨模块动作（如暂停周期上报）通过共享 `AppState`/信号通道通知调度层；
4. **命令下发（moonraker）为异步操作**：on_message 只记录待执行命令，由 moonraker_task/runtime_task 实际调用 `command.rs`，响应经 `notify_gcode_response`/回调回到模块。

### 8.4 固件行为转换层（Marlin → Klipper，新增，V1.1）

本项目为 **Klipper 平台**，R2 固件（M2/M1S，Marlin）仅为**行为参考**：其 GCODE 命令与硬件操作语义需**整体转换**到 Klipper 生态，而非照搬执行。转换层 `downlink/gcode_translator.rs` 覆盖**命令转换**与**硬件行为转换**两层：

| R2 命令/行为类别 | Klipper 侧执行方式 | 说明 |
|---|---|---|
| 基础 G/M（G28、M104/M140/M106/M107、M117、M114、M115、M220/M221…） | 直接下发 `printer.gcode.script` | Klipper 原生兼容（R4 核对） |
| U盘/文件类（M20/M21/M23/M24/M25/M26/M27/M28/M29/M30/M32…） | Klipper 兼容命令或翻译为 `server.files.*` + `printer.print.*` | Klipper 对 M23–M32 有限支持（R4 核对）；file_list 走 files API |
| 打印控制（M24/M25/M601/M602…） | `printer.print.pause/resume/cancel` + `SET_GCODE_OFFSET` 等 | 经 Moonraker print API |
| 调平类（G29） | 翻译为 `BED_MESH_CALIBRATE` | 经宏/直发 |
| 温度设定（M104/M140 预置） | Klipper `SET_HEATER_TEMPERATURE` 或宏 | preheat 逻辑由宏承载 |
| 风扇控制（M106/M107） | `SET_FAN_SPEED` 或 `fan_generic` 对象 | 硬件经 Moonraker |
| LED/蜂鸣器（M150/M300） | `SET_LED` / `output_pin` / `gcode_macro` | 硬件对象在 Klipper 配置声明（D15） |
| 断料检测（固件 runout 中断） | Klipper `runout_sensor` 对象 + 宏 | 经 Moonraker 订阅上报 |
| M2 自定义（M2001 等） | **Klipper `gcode_macro` 宏**实现 | 需与 Klipper 侧共同维护宏定义（OQ-08） |
| 无法转换 | 返回 `execResult:"ERR"` + 日志 | 不阻塞连接 |

> 转换表以 R2 §七「GCODE 子命令清单」逐条核对 R4（Klipper G-Code 文档）与 Klipper 对象配置后形成，属阶段 3 详细设计交付物。

### 8.5 告警映射（D14，新增）

| `notify_klippy_disconnected` / MCU 断连 | 1 | NA（已定义） |

## 10 协议数据模型（Rust struct ↔ JSON 字段映射）

### 10.1 公共约定

- 所有包含 `type`（String）、`id`（String）、`ts`（u64）。
- `id` = 设备 ID（默认 `G`+MAC）。

### 10.2 上行包字段映射

```json
{"type":"login","id":"G...","mb":"主板版本","sf1":"MCU版本","sf2":"ESP版本","wf":"WIFI名","ip":"IP","lang":0,"ts":123}
```

| Rust 字段 | JSON 字段 | 类型 | 必选 | 说明 |
|---|---|---|---|---|
| `type` | `type` | String | ✓ | 固定 `"login"` |
| `id` | `id` | String | ✓ | 设备 ID |

## 12 关键时序设计

### 12.1 登录

```
[Connected] → 发 login(直发) → [LoginPending]
  5s 无回复 → 重发（≤3 次）
  收到 login{bindState:0} → [Online] → 全量 4 状态包入 FIFO（1s 节拍出队）
  bindState:1/2 → [BindFail]（策略见 OQ-04）
```

### 12.2 周期上报

```
[Online] + 节拍(3s/60s) → 从 AppState（Moonraker 订阅）组装 4 状态包 → FIFO 出队（1s/个）
前置：login_success && 无登录/下载/固件/文件列表流程（R2 §6.1）
Moonraker 不可用：跳过或带"状态未知"标记（RSK-08）
```

### 12.3 文件下载（MQTT 握手 + Moonraker 执行）

```
下行 download_begin{url|serverIp,fileName,fileType}
  → 校验（U盘/忙闲/已有下载）
  → 回复 download_begin{OK,errCode:0} 直发
  → HTTP 下载（平台侧）→ 文件落盘到 Klipper 文件目录（~/gcode_files）
  → 下载结束发 download_end（1s×10 重发）
  → 收到 ackState 停止重发；否则 10 次后放弃并重置登录状态
  → 服务器后续下发 M32+M24（打印）或 M997（升级）：
     M32+M24 → 翻译层 → printer.print.start(filename)（Moonraker）
     M997     → 翻译层 → 升级宏（Moonraker，OQ-08）
```

### 12.4 file_list 分页

```
下行 file_list → 置标志 → 延迟 500ms（等 FIFO 排空，最多 2s）
  → moonraker server.files.list（根目录）→ 过滤 *.gco
  → 每页 ≤10 个直发
  → 无文件：fileTotal=0,fileIndex=0,fileList=[]
```

### 12.5 固件查询

```
[Online] 定时/UI → upgrade_query 直发
  收到 upgrade_query{serverIp,mcuFile,espFile}
    → 有 mcuFile/espFile（非 NA）→ 进入下载流程
    → 均 NA → 恢复周期上报
超时：有固件 120s / 无固件 60s（可配）
```

### 12.6 GCODE 执行时序（经 Moonraker，新增 V1.1）

```
下行 gcode{gcodeCmd:"G29N"} → GcodeModule
  → 翻译层：G29 → BED_MESH_CALIBRATE 序列（§8.4）
  → moonraker command.gcode_script(script)
  → Klipper 执行（notify_status_update 更新 bed_mesh/调平状态）
  → notify_gcode_response 收集执行结果/错误
  → 执行结束（Klipper 空闲 / 宏回报完成）→ MQTT gcode{cmdType,execResult:"OK"|"ERR"} 入 FIFO
  → 状态变化触发增量状态包（调平状态 status_level 等）
```

## 13 错误处理与日志

- 统一错误枚举 `AppError`：`ConfigError` / `NetError` / `MqttError` / `ProtocolError` / `FifoFull` / **`MoonrakerError`（WS 断连/JSON-RPC error/超时）**。
- 所有超限/失败路径记 `log::error`（`tracing`，std 平台），含状态机快照（对齐 `log_mqtt_reconnect` 风格）。
- 协议解析失败：丢弃该包 + 计数告警，不中断连接。
- 未知 `type`：忽略并计数（可扩展）。
- Moonraker JSON-RPC 错误：映射为 `execResult:"ERR"` 或 alarm，不中断 MQTT 连接。

## 14 非功能设计

### 14.1 内存预算（粗估）

| 项 | 大小 |
|---|---|
| transport 读缓冲 | 2048B |
| transport 写缓冲 | 2048B |
| MQTT client 缓冲 BUF_SIZE | 2048B |
| **Moonraker WS 收发缓冲** | 2×4096B（状态快照可达较大） |
| FIFO（10×枚举负载） | ≤1.5KB |
| 各模块状态（heapless 定长） | ≤2KB |
| 栈 + 运行时 | 按实际压测 |

常量：`MAX_TOPICS=8`（DOWN+LWT+预留）、`OUTBOX_DEPTH=8`。

### 14.2 性能

- 出队节拍 1s/包：单包发布最坏延时 <1s + 网络 RTT。
- MQTT 轮询 10ms、Moonraker 心跳 10s：均不阻塞 executor；CPU 占用通过压测验证（AC-13）。
- `notify_status_update` 增量 merge，避免整快照重建。

### 14.3 可维护性

- 协议模型、Moonraker 对接、业务模块三层分离；新增下行命令只需新增 `protocol` 结构体 + 模块处理函数（对齐 R2 §十扩展 SOP）。
- 翻译层（§8.4）以表驱动，新增 Klipper 宏/命令仅改配置或表项。

### 14.4 安全

- TLS feature 门控；明文模式仅限内网/调试。
- Moonraker `api_key` 支持（OQ-09）；配置文件权限与敏感项（password/api_key）脱敏。

| 风险 | 阶段 2 缓解措施 |
|---|---|
| RSK-01 myrtio-mqtt 无 std transport | StdTcpTransport 独立实现（§5）；trait 签名核验列入阶段 3 首项 |

| RSK-05 rustls 交叉编译 | TLS feature 门控默认关闭；备选纯 Rust provider |

## 17 交叉编译与部署设计

### 17.1 目标与工具链

- target：`armv7-unknown-linux-gnueabihf`
- 工具链（参考 rust-libp2p/p2p-camera）：`arm-rockchip830-linux-uclibcgnueabihf-gcc`
- 验证项：rustc 标准库（gnueabihf）与板端 uclibc 动态库 ABI 兼容性（RSK-06）；必要时改为 musl/静态链接或使用板端 libc 的 GNU 兼容层。

### 17.2 `.cargo/config.toml`（crates 根目录）

```toml
[build]
target = "armv7-unknown-linux-gnueabihf"

[target.armv7-unknown-linux-gnueabihf]
linker = "arm-rockchip830-linux-uclibcgnueabihf-gcc"
rustflags = [
  "-C", "link-arg=-Wl,--hash-style=gnu",
]
```

### 17.3 构建脚本（scripts/build_cross.sh）

```bash
#!/usr/bin/env bash
set -euo pipefail
export CC_armv7_unknown_linux_gnueabihf=arm-rockchip830-linux-uclibcgnueabihf-gcc
export CARGO_TARGET_ARMV7_UNKNOWN_LINUX_GNUEABIHF_LINKER=arm-rockchip830-linux-uclibcgnueabihf-gcc
# 若需静态链接 libgcc/libstdc++：
# export RUSTFLAGS="-C target-feature=+vfpv3 -C link-arg=-static"
cargo build --release -p mqtt-client
```

部署：产物 `target/armv7-unknown-linux-gnueabihf/release/mqtt-client` + `config/mqtt-client.toml` 拷贝到 RV1106，`systemd`/启动脚本拉起。Moonraker/Klipper 已在板端运行（本机 `127.0.0.1:7125`）。
